## 一、需求与系统分析

### 1.1 系统定位
本项目是一套**自助借书机系统**，读者可在借书机(Kiosk)上通过**扫码/读者证**自助完成借书、还书、续借、查询，管理员在管理端进行图书/用户/库存/借还管理。系统采用微服务架构，对外统一由 **API 网关 (8080)** 与 **Nginx (8090)** 暴露。

### 1.2 系统架构（被测对象全景）
| 层 | 组件 | 端口 | 职责 | 测试关注点 |
|---|---|---|---|---|
| 接入层 | Nginx | 8090 | 前端静态资源、反向代理、SPA 路由 | 静态可达、转发正确 |
| 接入层 | API Gateway(Spring Cloud Gateway) | 8080 | 统一入口、**JWT 鉴权过滤**、路由分发、白名单 | 鉴权、路由、白名单 |
| 服务层 | user-service | 8081/8091 | 登录/注册/用户管理/设置 | auth CRUD |
| 服务层 | book-service | 8082 | 图书/副本/库存/扫码 | Redis 缓存、库存状态机 |
| 服务层 | borrow-service | 8083 | 借书/还书/续借/借阅记录 | 业务规则、Sentinel 限流 |
| 服务层 | search-service | 8084 | Elasticsearch 检索/热词/推荐 | ES 一致性 |
| 服务层 | notify-service | 8085 | RabbitMQ 通知(短信/邮件) | 消息消费 |
| 服务层 | stats-service | 8086 | 借还统计/看板 | 统计正确性 |
| 中间件 | MySQL 3307 / Redis 6380 / ES 9200 / RabbitMQ 15672 / Nacos 8848 / Sentinel 8858 / Prometheus 9090 / Grafana 3001 | | | 数据/缓存/消息/监控 |

### 1.3 测试范围界定
**内测范围（in-scope）：** 网关 8080 暴露的全部 REST 接口、Nginx 8090 前端静态资源与反向代理、中间件数据一致性、缓存与数据库一致性。
**外测范围（out-of-scope）：** 第三方登录、真实短信/邮件发送、跨浏览器真实设备渲染（仅做可达性与契约分析）。
**测试环境：** Docker 全量微服务 + 中间件运行态（非 Mock），测试数据从数据库样例库读取。

### 1.4 风险分析与优先级
| # | 风险点 | 风险等级 | 测试重点 |
|---|---|---|---|

| R2 | Redis 缓存与 MySQL **一致性**、缓存穿透/击穿 | 高 | 数据与缓存验证 |
| R3 | 借还**库存并发扣减**是否原子、是否会超借 | 高 | 并发/库存一致性 |
| R4 | 借书机扫码→锁定副本→借出的**状态机** | 高 | 功能/状态机 |
| R5 | Elasticsearch 与 MySQL 数据一致性 | 中 | 数据一致性 |
| R6 | Sentinel 限流规则是否生效 | 中 | 性能/可用性 |
| R7 | 网关路由与 Nacos 发现是否稳定 | 中 | 冒烟/回归 |

## 二、测试策略 （Testing Strategy）

按 **测试金字塔** 分层，自底向上、逐层收敛：

- **L1 单元测试**（32 用例）：服务层业务规则、缓存逻辑、异常分支。
- **L2 契约测试**（6+）：Response 信封/实体结构作为前后端协议护栏。
- **L3 接口自动化**（50+ 用例）：对网关全部接口，覆盖业务流程闭环。
- **L4 端到端/冒烟**：核心链路（用户→借书→还书→续借→查询→统计）一键回归。
- **L5 专项质量**：安全、性能、兼容、数据一致性各专项独立执行。

**缺陷分级：** P0(阻断)、P1(严重)、P2(一般)、P3(建议)。

### 用例编号体系
```
<模块>-<类型>-<序号>
模块：AUTH(鉴权) USER BOOK BORROW SEARCH STATS SETTINGS GATEWAY SEC DATA PERF COMP
类型：FN(功能) SEC(安全) PERF(性能) DAT(数据) COMPAT(兼容) SMOKE(冒烟) REG(回归)
示例：BOOK-FN-07（图书功能用例 #7）、SEC-SEC-03（越权用例 #3）
```
