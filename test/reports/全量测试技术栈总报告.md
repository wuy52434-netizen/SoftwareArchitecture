## 三、执行详情与证据

### 3.1 单元测试（23/23）
- 位置：`backend/book-service/src/test`（16 条）、`backend/user-service/src/test`（7 条）
- 亮点：`BookService.getById` 用 `verify(mapper, never())` 实证**缓存命中不打 DB**；`updateStock→0` 状态切 `borrowed`；登录 4 大分支；`@Nested` 分组；JaCoCo 报告。

### 3.2 接口自动化（61 条，58 通过 / 2 已知缺陷 / 1 跳过）
- 覆盖：认证/图书 CRUD+扫码/借阅借用归还/用户管理/ES 检索/统计/设置。
- 工程化：session token 复用 + `fresh_client` 防污染、`BASE_URL` 可配、Allure + JUnit XML 双报告。
- 2 个标红即"真实缺陷用例"：
  - `KNWN-DEF-01`：统计看板图书数(24) ≠ 图书接口 total(25)，口径不一致。
  - `KNWN-SEC-02`：匿名 `PUT /api/settings` 返回 200，可未授权改系统配置。

### 3.3 安全与权限（13/14，XSS P1）
| 用例 | 结果 | 说明 |
|------|-----|------|
| SEC-AUTH-01 | PASS(缺陷记录) | 普通用户访问 /users 被拦但返回**500 而非 403**(KNWN-SEC-03) |
| SEC-XSS-02 | **FAIL** | 图书标题存 `<img onerror=alert(1)>` 未转义 → **存储型 XSS(P1)** |
| 其余越权/注入用例 | PASS | 注入/越权多数被拦截 |

### 3.4 数据与缓存一致性（10/11，1 P1 缺陷）
- **联通性证明**：篡改 Redis 缓存值后读接口返回篡改值 → 实证系统走 **Cache-Aside 读缓存**。
- **并发守恒**：借还无超卖、库存守恒。
- 缺陷：早期发现 **新建图书未同步 ES**（ES 24 vs DB 25）→ 本次回归复测 **已一致(24=24)**，需确认是否已由数据重跑修复，建议开发复核。

### 3.5 性能
**JMeter**：6000 请求 0 错误，读路径 P95 ≤108ms。
**Sentinel 补强（本次重点发现+修复）**：
- 缺陷：生产借阅接口 `POST /api/borrow` **未挂 `@SentinelResource("borrowBook")`**，限流规则空挂 demo 控制器，直连高并发**限流完全不生效**（blocked=0，全部穿透到业务层）。
- 修复：给真实借/还接口补注解 + blockHandler。
- 修复后复测：60 并发直连 → `blocked=155`，限流**真正拦截**。→ 回归脚本同步验证 `blocked>0`。

### 3.6 冒烟测试（10/10）
网关→鉴权→图书→ES→借还闭环→统计→设置→用户管理，快速判断"系统可交付"。

### 3.7 兼容性（10/11，新增 P2）
- 多接入层一致（网关/nginx）、多请求头兼容、方法/语义正确、中文无乱码均通过。
- **新增 P2**：非法分页 `page=-1`/`per_page=0` 触发 **HTTP 500**（应容错为默认或 400）。

### 3.8 AI 工具应用（方法论）
详见 `test/ai/AI工具在测试中的应用.md`：AI 完成缺陷归因（Sentinel）、用例生成、契约固化、回归清单编排 4 大实战案例 + 4 套可复用 prompt 模板。

## 四、缺陷清单（总）

| # | 级别 | 编号 | 缺陷描述 | 状态 | 发现层 |
|---|-----|------|---------|------|-------|
| 1 | P1 | SEC-XSS-02 | 图书标题存储型 XSS 未转义 | 待修 | 安全 |
| 2 | P1 | KNWN-DEF-01 | **图书数量多口径不一致**：DB `book_info`=43 本 vs 接口 total=25 vs 看板 totalBooks=24 vs ES 索引=24 条，四口径互不相同 | 待修(数据治理) | 接口自动化/数据一致性 |
| 3 | P1 | KNWN-DEF-04 | 新建图书不同步 ES（DB 新增但 ES 搜不到）| 待修(同步链路) | 数据一致性 |
| 4 | P2 | KNWN-SEC-02 | 匿名可 `PUT /api/settings` 改系统配置(返回200) | 待修 | 接口自动化/回归 |
| 5 | P2 | KNWN-SEC-03 | 越权访问 /api/users 返回 500 而非 403 | 待修 | 安全/回归 |
| 6 | P2 | COMPAT-P01 | 非法分页(page=-1/per_page=0)触发 HTTP 500 | 待修 | 兼容性 |
| 7 | P3 | ENC-01 | `language` 字段中文乱码(23 条) | 待修(数据) | 回归 |

> **已修复并回归**：① Sentinel 限流失效（真实借阅接口漏挂 `@SentinelResource`，已补注解+blockHandler+重启，并发从全部穿透→`blocked=155` 限流生效）。
> ⚠️ **数据口径说明**：测试中数据/安全层会经 API 创建校验书，DB `book_info` 累积至 43 本，而接口/看板/ES 各按口径返回 25/24/24——**这本身就是 KNWN-DEF-01 可复现的证据**；如需干净基线可执行 `docker/init.sql` 重置。

## 七、简历/答辩亮点小结
