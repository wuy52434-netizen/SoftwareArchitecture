## 二、四层技术栈详解

### 2.1 单元测试层（JUnit5 + Mockito + AssertJ + JaCoCo）

- **位置**：`backend/book-service/src/test`、`backend/user-service/src/test`
- **核心覆盖点**：
  - `BookService.getById`：验证**缓存旁路** —— 命中缓存不查库、未命中查库并回填 + 设 TTL(120s)、双未命中抛 `BOOK_NOT_FOUND`。
  - `BookService.createBook / updateBook / deleteBook`：ISBN 去重、副本创建、缓存清理、借阅中禁删。
  - `BookService.scanBook`：条码/ISBN 双路径扫码、空参异常。
  - `BookService.updateStock`：减到 0 → 状态转 `borrowed`。
  - `AuthService`：登录不存在(1001)/密码错(1002)/禁号(1003)/成功发 token；注册；刷新。
- **亮点**：`verify(mapper, never())` 验证"缓存命中绝不打 DB"；`ArgumentCaptor` 断言状态值；`@Nested` 按业务分组。
- **JaCoCo**：已接入 `backend/pom.xml` parent，`mvn test` 自动产出 HTML 覆盖报告。

### 2.2 契约测试层（Consumer-Driven Contract）

- **位置**：`test/contract/`
- **思路**：把"Result 信封 / 图书对象 / 分页 / 登录响应 / 分类"用 **JSON Schema** 固化为契约，线上抓真实响应逐条校验。供给侧/消费侧解耦时的协议护栏。
- **通过项**：6 个契约场景全部校验通过（含 ES 检索命中图书对象契约）。

### 2.3 接口自动化层（场景化黑盒）

- **位置**：`test/api/`（孤立目录，不依赖后端 Maven）
- **覆盖**：
  - 认证：正确登录拿 token、密码错误 1002、用户不存在 1001、空用户名、refresh 换新、`/me` 鉴权。
  - 图书：分页/标题搜索/分类筛选/空页、详情(缓存)、404、6 大分类、热门/新书、**创建→查→改→删闭环**、扫码。
  - 借阅：借阅记录列表、我的借阅、**借书→查→归还自清理闭环**。
  - **安全基线**：验证 `/api/books/**` 白名单匿名放行（借书机自助场景契约）、`/api/users/**` 无 token 必须 401。
- **工程化**：session 级 token 复用；独立 `fresh_client` 防 token 污染；`BASE_URL` 可配；产出 HTML + JUnit XML。

### 2.4 性能压测层（JMeter）

- **位置**：`test/jmeter/`
- **场景**：27s 压测，共发送 **6000 请求**，**0 错误率**，覆盖 4 条链路：
  - 登录 `/api/auth/login`（bcrypt 鉴权，平均 377ms —— 属加密哈希固有开销）
  - 图书列表 `/api/books`（Redis 缓存，平均 **52ms**）
  - 图书详情 `/api/books/{随机1-20}`（Redis 缓存，平均 **34ms**）
  - 关键词检索 `/api/search`（**Elasticsearch**，平均 **47ms**）
- **结果**：整体吞吐 **218~368/s**，读路径(列表/详情/检索)P95 ≤108ms。**4/4 采样零错误**，印证 Redis 缓存与 ES 检索的高吞吐、稳定读路径。登录因 bcrypt 密码哈希固有开销偏高，属预期。

## 三、运行方式

```bash
# ① 单元测试 + 覆盖率（driven by Maven wrapper）
python tmp/run_unit_tests.py

# ② 契约测试
cd test/contract && .python -m pytest -v --html=report.html

# ③ 接口自动化
cd test/api && .python -m pytest -v --html=report.html --junitxml=junit.xml

# ④ 性能压测
E:/apache-jmeter-5.6.3/bin/jmeter.bat -n -t test/jmeter/load_test.jmx -l result.jtl -e -o report
```

## 四、收获与简历亮点小结

1. **测试金字塔落地**：从底层业务规则单测到顶层压测，四个层级形成闭环，而非零散脚本。
2. **能讲透的深度点**：Redis Cache-Aside 单测、Sentinel 限流、认证白名单的契约测试、ES 检索的压测。
3. **工程规范**：独立 `test/` 目录自包含、`BASE_URL` 与环境变量可配、报告可接 CI（HTML/JUnit XML/JaCoCo/JMeter Dashboard）。
4. **可复现**：全流程一步一条命令，环境变量控制被测目标，任何人可复跑验证。
